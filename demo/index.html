Banco de pruebas del widget

Página de laboratorio con texto, color, imágenes y formularios para validar cada feature sin tocar la landing real.

Texto corrido

El widget de accesibilidad se instala con una sola línea de código y no requiere que el sitio anfitrión cambie nada más. Toda su interfaz vive dentro de un Shadow DOM, de modo que ni los estilos de esta página lo afectan a él, ni los suyos se filtran hacia acá.

Este párrafo largo existe para probar la lectura por voz: seleccioná cualquier fragmento y debería aparecer un botón contextual para escucharlo. También sirve para verificar que el aumento de tamaño de página reflowea correctamente, sin cortar palabras ni generar scroll horizontal. Podés combinarlo con la fuente para dislexia y comprobar que la métrica más ancha de OpenDyslexic no rompe el layout.

Fuente para dislexia

La columna izquierda usa la tipografía normal de esta demo. La derecha es una muestra estática de referencia: carga OpenDyslexic desde node_modules y aplica el mismo espaciado que la feature, para poder comparar sin togglear. Al activar la feature en el menú, toda la página debería quedar como la columna derecha.

Párrafos largos

La accesibilidad web no es una capa que se agrega al final: es una consecuencia de decisiones que se toman al principio. Un botón que no es un botón, un contraste elegido por gusto, un formulario sin etiquetas asociadas — cada uno de esos atajos se paga después, y lo paga alguien que no estuvo en la reunión donde se tomó la decisión.

Este segundo párrafo existe para probar una selección que cruce el límite entre dos bloques. Al arrastrar desde el párrafo anterior hasta acá, la selección abarca dos nodos distintos y el rectángulo de anclaje del botón debería quedar cerca de donde terminó el arrastre, no en el medio geométrico de todo lo seleccionado.

Sitio “mal comportado” (px fijos)

Este bloque imita un sitio hecho todo en píxeles: ancho fijo, alto fijo y font-size en px. Escalar el font-size del <html> no lo mueve ni un pixel — es el caso que justifica la estrategia de fallback con transform: scale().

Tarjeta de 420 px

Todo acá está en px: el ancho del contenedor, el tamaño de fuente y el alto de la caja. Con la estrategia font-size este texto no cambia; con transform sí.

Este párrafo, en cambio, no declara font-size: hereda del <html> y por lo tanto sí escala con la estrategia primaria. Compará los dos mientras subís el tamaño.
